## 1. 目的と前提

医学・学術論文（主に日本語）のPDF・画像を取り込み、本文にマーカーとメモを付け、書誌情報とバンクーバー方式の参考文献を作るWebアプリ。

| 前提     | 内容                                                             |
| -------- | ---------------------------------------------------------------- |
| 利用者   | 開発者＋招待した1名（非公開）                                    |
| 費用     | 月額0円（無料プランのみ）                                        |
| 優先順位 | データ保護 → 正確性 → セキュリティ → 使いやすさ → 保守性         |
| 開発者   | プログラミング初学者。HTML → CSS → JavaScript の順に段階的に作る |

**現在の位置づけ**：すべてブラウザの中で動くローカル版。データはブラウザ内（IndexedDB）にだけ保存される。クラウド保存（Supabase）・ログイン・公開（Vercel）はこれから。

## 2. 全体構成

```
┌──────────────── ブラウザ（あなたのPC） ────────────────┐
│  index.html ─ styles/style.css ─ src/main.js            │
│     │                                                    │
│     ├ 画面（src/ui/）  ライブラリ・格納・閲覧・パネル     │
│     ├ PDF（src/pdf/）  PDF.js で描画・文字の取り出し       │
│     ├ 処理（src/import, highlights, metadata, citation） │
│     └ 保存（src/storage/）→ IndexedDB（ブラウザ内DB）     │
└─────────────────────┬────────────────────────────────────┘
                      │ /api/...（DOI・タイトルなどの検索語だけ）
┌─────────────────────▼────────────────────────────────────┐
│ Vite 開発サーバー（vite.config.js）＝外部APIへの中継        │
└──┬──────────┬──────────┬──────────┬──────────────────────┘
   ▼          ▼          ▼          ▼
  JaLC     Crossref    PubMed    J-STAGE
```

- **フレームワークは使わない**（素の JavaScript）。初学者が読める・直せることを優先。
- 追加したライブラリは **PDF.js（pdfjs-dist 6.5.438）だけ**。開発用に Vite・Vitest。
- **PDF・画像は外部に送らない。** 外部に送るのは DOI・タイトルなどの検索語だけ。

## 3. 画面設計

### 画面（URL のハッシュで切り替える：`src/router.js`）

| URL              | 画面                             | 主な内容                                                                               |
| ---------------- | -------------------------------- | -------------------------------------------------------------------------------------- |
| `#/library`      | 論文ライブラリ                   | アップロードの入口カード、検索欄、論文一覧                                             |
| `#/upload`       | 論文の格納                       | ドラッグ＆ドロップ、アップロードのポイント、進み具合、保存前の確認、格納された論文の表 |
| `#/search`       | ライブラリ（検索欄にフォーカス） | ―                                                                                      |
| `#/paper/論文ID` | 論文閲覧                         | PDF・画像の表示、書誌情報、マーカー、メモ、参考文献                                    |
| `#/settings`     | 設定                             | 開発予定                                                                               |

### デザイン方針

- ミニマル・落ち着いた配色・大きめの文字・十分な余白（ChatGPT風のシンプルさを参考にした独自デザイン）。
- 色・文字サイズ・余白は **CSS変数**（`:root`）で一元管理。アクセントは深緑 `#2D5A4A` の1色。
- 主な文字サイズ：大見出し27px／セクション22px／論文タイトル19px／本文17px／ボタン16px。
- **色だけで状態を伝えない**（「✓」「エラー：」「開発予定」などの文字も表示）。
- 未実装の機能は「開発予定」と表示し、押せないようにする。

### レスポンシブ

| 画面幅                      | 配置                                                   |
| --------------------------- | ------------------------------------------------------ |
| 1024px以上（PC）            | 文字付きサイドバー（開閉できる）＋ 論文と右パネルの2列 |
| 768〜1023px（タブレット）   | サイドバーはアイコンだけ。論文の下にパネル             |
| 767px以下（スマートフォン） | 上部メニュー。格納画面の表は1件ずつ縦並び              |

狭い画面では、ファイル選択後の進み具合・保存ボタンが見える位置まで自動でスクロールする。

## 4. データ設計（IndexedDB：`research-marker-local`、版2）

将来の Supabase のテーブルと同じ分け方にして、クラウドへ移しやすくしている。

```
papers（論文・書誌情報）
 ├ sourceFiles（元ファイルの情報）── fileBlobs（元ファイルの中身。変更しない）
 ├ pages（ページ：表示・マーカーの単位）
 └ highlights（マーカー・メモ）……版2で追加
```

| 表          | 主な項目                                                                                                                                                                                                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| papers      | id、title、displayName（ファイル名）、authors、journal、journalAbbr、year、volume、issue、pageStart、pageEnd、doi、pmid、language、titleEn・authorsEn・journalAbbrNlm（NLM形式用）、**fieldSources（項目ごとの取得元と日時）**、bibliographyLookup（自動取得の結果）、sourceKind、pageCount、createdAt、updatedAt、deletedAt、sync |
| sourceFiles | id、paperId、kind、mimeType、originalName、size、**sha256**、width・height、orderIndex                                                                                                                                                                                                                                             |
| pages       | id、paperId、sourceFileId、sourceIndex（PDFの何ページ目か）、orderIndex、kind、**textStatus**（has-text／no-text／image）、width・height                                                                                                                                                                                           |
| highlights  | id、paperId、**pageId**、pageIndex、color、**quads（正規化座標の4点の四角形）**、quoteText（選んだ文字そのまま）、quoteNormalized、prefix・suffix、memo、updatedAt、deletedAt、clientRequestId                                                                                                                                     |

### 共通のルール

- **削除は論理削除**（`deletedAt` を記録して一覧から外すだけ。データは残す）。
- **重複の防止**：ファイルの指紋（SHA-256）で、同じファイルの二重登録を拒否する。
- **上書きの防止**：更新時に `updatedAt` を比べ、別の画面で先に更新されていたら保存しない。
- **保存の確認**：1つのトランザクションでまとめて保存し、読み直して SHA-256 が一致してから「保存完了」と表示する。
- **クラウド移行の準備**：各データに id・SHA-256・`sync`（同期状態）を持たせ、移行時の重複・消失を防ぐ。

## 5. 主な処理の流れ

### 5-1. 取り込み（`src/import/`、`src/ui/importPanel.js`）

1. ファイルを選ぶ（ボタン、またはドラッグ＆ドロップ）
2. **中身の先頭バイトで形式を判定**（`%PDF`・`FF D8 FF`・`89 50 4E 47`）。拡張子との不一致、容量の上限（PDF 30MB・画像20MB・100ページ）を確認
3. SHA-256 を計算し、重複を確認
4. PDFはページごとに文字情報の有無を判定、画像は大きさを取得
5. 保存前の確認（タイトルの入力、画像の並べ替え）→ 保存 → 読み直して確認
6. 保存後、裏側で書誌情報を自動取得（5-4）

### 5-2. 閲覧（`src/ui/viewer.js`、`src/pdf/pdfjs.js`）

- メモリ節約のため、**表示中の1ページだけ**を描画する。canvas の画素数にも上限を設ける。
- 拡大率は「表示エリアの幅＝100%」を基準に 50〜300%。画面幅が変わると描き直す。
- 日本語PDFのため、CMap・標準フォントなどを `public/pdfjs/` から読み込む（`npm run dev`／`build` の前に自動コピー）。

### 5-3. マーカー・メモ（`src/ui/markerPanel.js`、`src/highlights/`）

- PDF.js のテキストレイヤー（透明な文字）で、本文の文字を選べるようにする。
- 選んだ範囲の位置を **ページ正規化座標（左上0・右下1）** の4点の四角形に変換して保存する。
- 描画は SVG（`viewBox="0 0 1 1"`）。そのため、拡大・縮小、画面幅の変更、再読み込みのあとも位置がずれない。
- ページの重なり順（下から）：canvas → マーカー（SVG）→ テキストレイヤー。
- メモは、入力をやめて0.8秒後に自動保存する。別のマーカーを選ぶ前にも保存する。

### 5-4. 書誌情報の自動取得（`src/metadata/`）

```
PDF の文書情報・1〜2ページ目の文字
  ├ DOI あり → 日本語：JaLC（→ Crossref）／英語：Crossref（→ JaLC）
  │            → PubMed で NLM 形式の著者名・略誌名・英語タイトルを補う
  │            → 取得したタイトルが PDF の文字と一致したら、空いている項目だけ自動で反映
  │            → 一致しなければ「要確認」として結果を表示し、利用者が選ぶ
  └ DOI なし → 1ページ目のいちばん大きな文字（タイトルの候補）で
               J-STAGE（日本語）／Crossref（英語）を検索 → 候補から利用者が選ぶ → JaLC 等で取得
画像・スキャンPDF → 「DOI またはタイトルで探す」欄に入力して検索（OCR は未実装）
```

- 入力済みの値は勝手に上書きしない（違う値は「今の値」と並べ、チェックを外して表示）。
- 項目ごとに取得元（JaLC・Crossref・PubMed・手入力）を記録・表示する。
- J-STAGE の結果は表示するだけで保存しない（24時間以上の保存は規約で禁止）。「Powered by J-STAGE」を表示する。

### 5-5. 参考文献（`src/citation/vancouver.js`）

- バンクーバー方式。区切りは半角。`著者. タイトル. 略誌名. 発行年;巻(号):ページ.`
- 国内形式（日本語論文の既定）と NLM 形式（英語論文の既定）。日本語論文を NLM 形式にすると `[英訳タイトル]` と末尾に `Japanese.` を付ける。
- 著者7名以上は最初の6名＋`et al.`（`ほか`・`他` も選べる）。ページは省略しない形式（`758-761`）が既定。
- 著者・タイトル・略誌名・発行年が足りないと、コピーできない（推測で埋めない）。

## 6. 重要な設計判断と理由

| 判断                                     | 理由                                                                                                     |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 位置を**正規化座標（0〜1）**で保存       | 表示の大きさや端末に左右されず、同じ位置に描ける。将来のOCR（傾いた写真）でも同じ形式を使える            |
| 形式を**ファイルの中身**で判定           | 拡張子は名前を変えるだけで偽れるため                                                                     |
| **SHA-256** で重複・保存内容を確認       | 同じ中身なら必ず同じ値になり、ファイル名が違っても重複を見分けられる。保存が壊れていないかも確かめられる |
| **推測で書誌情報を作らない**             | 医学論文の参考文献の正確性を守るため。テスト中にも、想定していたDOIが実在しないことが見つかった          |
| 自動反映は**タイトルが一致した場合だけ** | 参考文献欄の別の論文のDOIなどを取り違えないため                                                          |
| 外部APIは**開発サーバーで中継**          | ブラウザから直接呼ぶと断られるAPIがあるため。公開時はサーバー処理に置き換える                            |
| 比較用の文字だけ正規化                   | 日本語PDFの部首の文字（`⻑` など）でも検索・照合できるようにしつつ、元の文字は変えないため               |
| **論理削除**                             | 誤って削除したデータを戻せるようにするため                                                               |
| フレームワークを使わない                 | 学習目的で、仕組みを理解しながら保守できるようにするため                                                 |

## 9. 既知の制約

- **データはこのブラウザの中にだけある**。閲覧データの削除で消え、別の端末・ブラウザでは見えない。元のファイルは手元にも残すこと。
- `http://localhost:5173/` は自分のPCからしか開けない。他の人に見せるときは画面共有を使う。
- 書誌情報の自動取得には、インターネット接続と開発サーバー（`npm run dev`）の起動が必要。
- スキャンPDF・画像はマーカーを引けず、書誌情報も自動では読み取れない（OCR は未実装）。
- 削除したデータを元に戻す画面はまだない（データ自体は残っている）。
- 医中誌の略誌名辞書との照合、CiNii での検索は未実装。
